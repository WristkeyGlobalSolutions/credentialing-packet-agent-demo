How it submits — once, and only once

Every packet gets a fingerprint (idempotency key) from its ID + document text on arrival. Submit the same packet again — double-click, retry, crash-and-restart — and the key is recognised and blocked.

State machine: RECEIVED → VERIFYING → PAUSED / IN_REVIEW / NEEDS_INFO / READY → SUBMITTED. Illegal jumps crash on purpose. No shortcuts.

🔒 Rules outrank AI, always

An expired license stops the packet even at 95% model confidence. A date is a date — deterministic code decides, not the model.

∅ Blank is safer than a guess

If the quote doesn’t verify or confidence is <70, the field stays empty and goes to a human. The agent abstains on purpose.

⏸ Pause is a feature

Portal login needs a human code. The agent parks with state saved and resumes exactly where it left off — it never logs in alone.

About this demo: Interactive browser version of the Credentialing Packet Agent prototype built for the Assured Health conversation — synthetic packets only, no real PHI. Architecture mirrors the original TypeScript prototype: deterministic.ts (rule checker), models.ts (cheap → expensive routing), gate.ts (90 / 70 bands), agent.ts (orchestrator + state machine), audit.ts (append-only log). Closing line for the demo: “That is how I build agents. Small rules first. Proof for every answer. A human where a human belongs.”
